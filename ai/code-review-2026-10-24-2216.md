## Findings

### AUD-01 — P1: Native API defaults to unauthenticated access on all interfaces

**Confidence:** High. **Category:** Security / trust boundary.

**Locations:** `server/main.go:16-19,62-67`; `server/api.go:131-241`; `server/terminal.go:117-130`; `scripts/build.sh:31-35`; `scripts/dev.sh:21`.

The default server address is `:8787`, and dev builds stamp `:8788`. The handler has no authentication middleware. A caller can replace the Telegram connection, list pairing codes, and approve a pairing. The approved sender can then submit `$ <command>`, which starts a shell without an LLM or sudo password. This is a source-confirmed takeover chain for a network peer able to reach a native listener. No real bot, remote takeover, or live listener scan was used in this audit.

**Impact:** Arbitrary command execution as the service user. Compose publishes its host port on loopback, mitigating exposure through that publication; it does not repair native defaults or provide API authentication.

**Recommendation:** Use loopback native defaults and authenticate control routes. Keep Docker's required internal binding explicit rather than changing all deployment defaults indiscriminately. A per-install token is smaller than a new account system; a protected Unix socket is another option.

**Validation:** Verify default listener addresses in native/dev builds, unauthenticated mutation rejection, authenticated CLI operation, and Docker health/API connectivity.

### AUD-02 — P1: Restore deletes live data before preserving or extracting its input

**Confidence:** High. **Category:** Data preservation / recovery.

**Locations:** `scripts/omni-docker-backup.sh:69-88`.

After checking that the archive lists a `home/` entry, restore runs `find . -mindepth 1 -delete` inside the live home, then extracts the backup. There is no staged replacement or rollback. If the archive resides inside that home, deletion removes both live data and the archive before extraction opens it. This is possible with the installer's bind-home layout and an input such as `$OMNI_DIR/home/backup.tgz`. The EXIT trap starts the service even after extraction fails.

**Evidence:** A fake-Docker probe executed the actual shell command with mount paths translated to temporary directories. A valid input archive inside the target home passed preflight; restore exited 2, both the original sentinel file and archive disappeared, and `compose start` was recorded. This used host GNU tar and filesystem commands, not an actual Alpine container.

**Recommendation:** Reject overlapping input/target paths, preserve the input outside the target, extract and validate into separate staging storage, and retain the original until replacement succeeds. On failure, keep the service stopped or restore the original before starting. Staging requires additional disk space, which should be checked first.

**Validation:** Exercise input inside home, insufficient space, extraction failure, interrupted restore, and successful restore. Each failure must preserve a usable installation or recoverable original.

### AUD-03 — P1: Chat file confinement follows symlinks outside its root

**Confidence:** High. **Category:** Security / filesystem boundary.

**Locations:** `server/media.go:133-148,167-225,321-348`.

`resolveJailed` checks a cleaned string prefix, then file operations follow ordinary filesystem symlinks. A symlink within `filesDir()` can therefore expose an outside target to `read_file` or `send_file`, or redirect writes through an intermediate symlink. `read_file` is not in the default approval set. Exploitation requires an existing symlink, potentially created by the owner, a privileged agent, or restored state; chat tools do not themselves create symlinks.

**Evidence:** `TestAuditSymlinkEscape` created a temporary outside sentinel and an in-jail symlink. Calling the real `fileTool` read the outside sentinel successfully.

**Recommendation:** Use root-relative filesystem operations with an enforced containment boundary, accounting for intermediate components and write paths. A lexical check or one pre-operation symlink resolution is insufficient against replacement races. This adds filesystem-policy handling but preserves the advertised chat contract.

**Validation:** Test final/intermediate symlinks for read, write, edit, and send operations, nonexistent write targets, and concurrent path replacement.

### AUD-04 — P1: Telegram transport errors retain bot tokens

**Confidence:** High. **Category:** Security / secret disclosure.

**Locations:** `server/telegram.go:124-139,243-253,292-300,341-347`; `server/main.go:50-53`; `server/api.go:150-155`.

Telegram URLs include the bot token. `Telegram.call`, download, and upload return HTTP transport errors unchanged; callers log or serialize those errors. A transport failure can therefore disclose the token in raw service logs or API responses. Doctor and `/ops logs` redact selected display output, after the sensitive error has already escaped. Guardian's `tgCall` already handles this differently.

**Evidence:** `TestAuditTokenError` used an in-memory failing HTTP transport and a synthetic token. The returned `GetMe` error contained that token. No real credential or journal was read, and this audit does not assert a current production leak.

**Recommendation:** Sanitize at the Telegram HTTP boundary before returning errors. Apply the same policy to download/upload failures. Review Gemini query-key errors and raw CLI stderr as related disclosure paths. Centralization avoids separate log/UI redaction drifting again, at the cost of less raw diagnostic detail.

**Validation:** Use sentinel secrets in connection, timeout, redirect, download, and upload failures; assert they never enter returned errors or logs.

### AUD-05 — P1: Failed update omits the current binary from rollback

**Confidence:** High. **Category:** Reliability / installation recovery.

**Locations:** `guardian/main.go:584-600`.

The updater moves the current binary to `.prev`, attempts its replacement, and adds the binary to `installed` only after replacement succeeds. If writing or renaming its replacement fails, `rollbackBins(installed)` excludes that current binary. The error report nevertheless says previous binaries were restored. Backup-rename errors are also ignored.

**Evidence:** `TestAuditRollbackMissingCurrent` reused the existing fake release/service harness and placed a directory at `omni-server.tmp`. The real updater restored the earlier CLI, left `omni-server` missing with its old `.prev` intact, and emitted the false restoration claim.

**Recommendation:** Stage replacements before moving live binaries, check backup moves, track each moved binary immediately, and include the failing binary in recovery. Report rollback failures explicitly. A small operation ledger is preferable to rewriting the updater framework.

**Validation:** Inject failure after each backup, write, and rename for all three binaries. Assert every original remains runnable and reported recovery matches filesystem state.

### AUD-06 — P1: Task execution continues despite failed durable state writes

**Confidence:** High for control flow; runtime failure consequences inferred. **Category:** Reliability / external side effects.

**Locations:** `server/task.go:118-169,223-244`; `server/store.go:603-611`.

The task loop ignores `BumpTaskStep` and `SetTaskStatus` errors. After a successful agent iteration, a failed step write leaves the old step eligible to run again. A failed DONE write still produces a completion notification while the database can remain `running`, allowing replay after restart. Merge results are removed before the following state advancement is checked. Worker result writes are also unchecked.

**Impact:** Repeated external actions, lost worker evidence, or a false completion report during database/filesystem failure. Existing success-path tests do not establish safe failure behavior. No real external action was repeated for this audit.

**Recommendation:** Stop on failed mandatory persistence; preserve evidence until progress is durable; notify completion only after successful status storage. Where external effects cannot be transactional, use operation-specific idempotency or reconciliation. Merely checking SQLite errors cannot guarantee exactly-once external execution.

**Validation:** Inject database update failures and result-write failures after successful fake agent work. Confirm no automatic duplicate action, no premature success, and recoverable checkpoint/results.

### AUD-07 — P2: Restored environment is not applied to the existing container

**Confidence:** High. **Category:** Correctness / Docker integration.

**Locations:** `scripts/omni-docker-backup.sh:76,80-88`; `docker-compose.yml:15`; `scripts/docker-entrypoint.sh:156-161`.

Restore writes portable keys into `.env`, then its EXIT trap calls `docker compose start`. That starts the existing container with its previously created environment. Changed bot tokens, API keys, timezone, plugins, or guardian interval do not become its new environment. Environment credentials take precedence over restored YAML credentials, so stale environment values can mask restored settings.

Docker documents that [start uses existing containers](https://docs.docker.com/reference/cli/docker/compose/start/), whereas [up recreates containers when configuration changes](https://docs.docker.com/reference/cli/docker/compose/up/). The application of these semantics to this script is an inference from its control flow and `env_file` configuration; no actual container was recreated during this audit.

**Recommendation:** After successful data and environment restoration, recreate the service with the updated environment and verify health. Keep this separate from failure recovery in AUD-02. Recreation has startup cost and may rerun post-start installers.

**Validation:** Restore different sentinel values, inspect container environment, and check effective token resolution, timezone, and guardian interval. Confirm failed restores do not launch a fresh installation accidentally.

### AUD-08 — P2: Persistent shell hangs when output lacks a trailing newline

**Confidence:** High. **Category:** Correctness / process protocol.

**Locations:** `server/terminal.go:355-360,483-503`.

The shell probe prints its nonce immediately after the command's output. The reader recognizes it only at the beginning of a line. `printf hi` therefore produces `hi<nonce>...`; the reader consumes the line as output and waits forever for another sentinel. The shell is alive and idle, while the terminal worker stays busy. The idle timer intentionally does not kill busy sessions.

**Evidence:** `TestAuditMissingNewline` called the real persistent shell with `printf hi`, observed no completion within 150 ms, and explicitly killed the temporary shell for cleanup. Source explains the deterministic framing failure; this was not a performance timeout claim.

**Recommendation:** Frame the sentinel independently of user output, or parse a nonce delimiter independent of line starts. Preserve the command's original exit status and output when changing framing. Avoid changing the separate one-shot protocol unnecessarily.

**Validation:** Cover empty output, no newline, multiline output, nonzero exit with no newline, consecutive commands, bash/zsh, and interruption.

### AUD-09 — P2: Config writers can lose keys or overwrite corrupt input

**Confidence:** High. **Category:** Reliability / duplicated state ownership.

**Locations:** `server/config.go:49-68`; `cli/main.go:243-262`; `cli/plugins.go:336-366`.

Multiple processes implement independent YAML read/modify/write operations against the same file. They ignore YAML decoding errors and write directly in place. Concurrent CLI/server changes can overwrite unrelated updates; malformed input can be replaced by a partial configuration; interrupted writes can truncate credentials and settings. Passing mode 0600 to `WriteFile` also does not repair an existing file's mode.

**Recommendation:** Share the small configuration persistence implementation; reject malformed existing input, serialize cooperating writers, and write a restricted temporary file followed by atomic replacement. Atomic rename alone prevents truncation but not lost updates. Cross-process locking adds coordination, justified by actual writers already present.

**Validation:** Concurrently change two different keys, inject interrupted writes, supply malformed YAML, and start with permissive permissions. Verify unrelated values and restrictive permissions survive.

### AUD-10 — P2: Context display measures a different prompt than chat sends

**Confidence:** High. **Category:** Correctness / duplicated computation.

**Locations:** `server/context.go:29-34,41-74`; `server/chat.go:205-212`; `server/ai_memory.go:146-173`.

Chat includes persona, cron, files, tasks, plans, core memory, optional planning instructions, and query-specific recall. `/context` counts persona plus cron and reads the older long-term memory page instead of that recall. It can report substantially more free space than the actual prompt has. Both paths also estimate content without all rendered framing, so the display is not a hard context-fit guarantee.

**Recommendation:** Reuse prompt-section composition for generation and accounting, or explicitly label unavailable query-dependent sections. Keep estimates cheap; an exact tokenizer is unnecessary to eliminate structural omissions. Sharing section assembly must avoid issuing duplicate memory calls just to render a status panel.

**Validation:** Compare counted sections with assembled prompts containing files/tasks/plans/core memory and planning mode. Test missing memory service and bounded history.

### AUD-11 — P2: Reasoning effort setting is saved and displayed but never used

**Confidence:** High. **Category:** Correctness / incomplete configuration.

**Locations:** `cli/main.go:477-533`; `server/config.go:19-21`; `server/llm.go:251-261`; `server/answer.go:147-185,217-306`.

`omni llm model -e high` persists the provider effort and status displays it. Repository-wide searches show server effort values are read only to construct status. Neither `cliArgs` nor `askAPI` includes an effort setting in the actual invocation/request. Users can change a setting that appears active while generation retains provider defaults.

**Recommendation:** Either implement effort for supported generation paths or reject/label unsupported combinations. Keep provider-specific capability handling small. Current external provider/CLI support was not checked, so this report does not prescribe flags or request fields.

**Validation:** Assert actual fake CLI argv and HTTP request bodies for each supported effort path, and explicit rejection for unsupported paths. Saving/display tests alone do not verify behavior.

This audit did not run real document prompt-injection, multi-owner abuse, or privileged sudo experiments; it does not claim those risks are mitigated.
