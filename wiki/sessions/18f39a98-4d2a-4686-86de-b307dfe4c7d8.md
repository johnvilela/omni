# One version again, LLM provider integrations, and Telegram auto-answer (2026-09-01, 16:45–18:22)

Reverted the previous session's per-service versioning: "there will exists only one version on omni, not one version per service." Restored a single `version/version.go` (`const Version = "v0.1.0"`), aliased by both `cli/main.go` and `server/main.go` as `const version = omniversion.Version`, and restored the `omni status` version-mismatch alert — meaningful again now that a cli/server difference always means a stale binary. `wiki/api.md`/`install.md`/`index.md` were updated to match; this is the versioning story now recorded in [[api]] and [[install]].

Then built the LLM provider integration: "integration with just: openai (using oauth or api key), claude (using oauth if possible and api key), gemini (using oauth or apikey). On claude if the oauth doesn't work, we will use the claude code as interface." Refined through plan mode to: plumbing only (nothing consumes an LLM yet at this point), "oauth" = reusing whatever credentials a vendor CLI (`codex`/`claude`/`gemini`) already stored on disk — no OAuth flow written in omni — and the claude fallback = shelling out to a `claude` binary found on PATH. Implemented `server/llm.go` (credential resolution ladder, api-key validation via a models-list call, `llmStatuses()`), three `/llm*` routes mirroring the channels routes, new `openai_key`/`anthropic_key`/`gemini_key` config.yaml fields, and CLI commands `omni llm` / `omni llm connect [-p provider]` mirroring `omni channels`. Along the way, fixed a latent bug: `saveToken` clobbered `config.yaml` with a fresh one-key map on every save — replaced with a read-merge-write `saveConfigKey` so telegram and llm keys coexist. No new Go dependency was needed — see [[dependencies]]. Full route/behavior detail lives in [[api]].

Added `omni llm set-default [-p provider]` next: "save the selected llm as default... Save this information on the yaml config file... so it can be easily backuped and moved to a new PC." Design: the CLI writes `default_llm` to config.yaml, the server only reads it into the `default` field on `GET /llm` — keys and default live in the same one file. The user's own answer decided a specific edge case: connection intent stays in SQLite even after a config.yaml move to a new PC (rather than being cleared), because a future `omni doctor` command (explicitly not built now) is meant to flag a default pointing at a disconnected provider. A follow-up, "If only one llm is connected, that llm is set as the default", added a computed (never persisted) implied default: with no explicit `default_llm` and exactly one provider connected, that one reports as default; an explicit `set-default` always wins, and the implied default self-heals as connections change.

The main feature: "make the default IA answer the TEXT received by the telegram and send back a response... simple text input-output." New `server/answer.go`: `api_key` sources call the provider API directly with hardcoded cheap models (`gpt-4o-mini` / `claude-3-5-haiku-latest` / `gemini-2.0-flash`); `oauth`/`claude-code` sources shell out to the vendor CLI (`codex exec` / `claude -p` / `gemini -p`) because stored CLI tokens aren't usable for direct API calls. `server/reverse.go` was deleted — the old rune-reverse echo is gone for good; no default, or a disconnected default, replies with a `⚠` notice instead of silence.

A screenshot showed openai failing as default. Root cause: not a credentials problem — `codex exec` refuses to run outside a trusted/git directory unless given `--skip-git-repo-check`, and the server's systemd working directory isn't trusted. Fixed with that one flag; confirmed while debugging that codex's stdout is already clean (progress/banner noise goes to stderr) and its default sandbox is already read-only with no-approval, so nothing else needed changing. Asked to compare against OpenClaw/opencode, the conclusion (recorded in [[openai-codex-backend]]) was to keep the CLI shell-out for both providers — OpenClaw does the identical `claude -p` shell-out for Claude and Anthropic's support policy sanctions it as billing the subscription; opencode's faster direct-HTTP route for openai exists but carries token refresh, request rewriting and quota tracking to survive an unofficial endpoint.

Last addition: a Telegram "typing…" indicator, because "i sent the message and it felt like nothing was happening." `sendChatAction` (action `typing`) is re-sent every 4s from message-arrival to answer-ready (Telegram only displays it ~5s per call), best-effort — a failed typing call never blocks the reply; the test blocks the stub answer until a `sendChatAction` call arrives, proving the ordering.

Also hit and recorded a scripting gotcha while smoke-testing with throwaway servers — see [[gotchas/fish-syntax-in-bash-tool]].

All of this session's work (version revert, llm plumbing, set-default, implied default, telegram auto-answer, codex fix, typing indicator) remained uncommitted throughout, per the project's "commit only when asked" rule.
