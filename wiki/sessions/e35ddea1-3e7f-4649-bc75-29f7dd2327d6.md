# `/terminal` shell mode and `$` one-shot commands (2026-09-03, 13:31–16:16)

Opened with a concrete feature ask: "`/terminal`" should stop using any LLM and let commands be sent straight to the omni-server host's shell, always with sudo, asking the PC password only once at the start; plus a `$ <cmd>` syntax for one-shot commands outside terminal mode (e.g. `$ cd ..`). The user invited "Ask me anything to refine this," but the open questions were resolved through deep codebase exploration instead of a Q&A round: two Explore passes mapped `handleMessage`'s routing switch (the `!`-prefix interrupt was the exact precedent for a `$`-prefix one-shot), confirmed there was no existing shell/SSH/sudo/password code anywhere in the repo, found the one generic exec helper (`runCLI`) sets no `cmd.Stdin` so sudo piping needed new plumbing, and — critically — established that omni is three binaries on a single machine with Telegram as an outbound-only transport: "my other PC" from the user's phone is really the server host itself, so "send commands to my other PC" means running them locally in the server process, as the systemd-user-unit's (non-root) user. A Plan agent then produced the design, followed to completion.

## What shipped, in the order it was built

- **v0.18.0 — first cut**: `/terminal` prompts for the sudo password once, spawns a persistent **root** `bash`, and every following message runs in it (so `cd`/env/background jobs persist); `$ <cmd>` runs as the normal user with sudo only when the command contains `sudo`, prompting for the password fresh every time (never cached). The password is validated, used immediately, then discarded — never written to disk or SQLite — and its Telegram message is deleted via a new `DeleteInbound` flag on `tgReply`.
- **Folder prompt**: user asked every reply to lead with the current directory and git branch, like a screenshot they shared. Added a `📁 <path> (<branch>)` prompt line captured from the shell's own `$PWD`/`git branch --show-current` via the same sentinel that already reports exit codes — so it tracks the *real* cwd after every `cd`.
- **Trim + apply to one-shot too**: user asked the `$` one-shot to show the same prompt, and the path trimmed to its last two segments. Added `shortPath`, applied to both paths (`/home/jv77/Documents/dev/omni` → `dev/omni`).
- **Password retry**: user reported that mistyping the password once kicked them out of terminal mode entirely. Root-caused to `applyPassword` clearing the pending state unconditionally — fixed to only clear on success or give-up, with a retry loop (`maxSudoTries=3`) that tells the user how many attempts remain, "like linux does."
- **Default shell, then all three shells**: user asked terminal mode to always use the login shell (fish, in their case). Live investigation (mkfifo pipe tests, then PTY-driven Python scripts) established that fish reads its **entire stdin to EOF before executing anything** over a plain pipe, and only runs incrementally under a real PTY — whose output floods with line-editor redraw codes that would need a full terminal-emulator parser to strip. Broadened immediately to "must work with all 3 main shells: fish, bash and zsh," landing on a **Mixed model**: one persistent shell process for bash/zsh (full `cd`/env/bg-job persistence), but a fresh `fish -c` per command for fish, with cwd tracked in Go between commands (env vars and background jobs don't persist for fish). `defaultShell()` resolves the login shell via `getent passwd <uid>` field 7; the sentinel probe syntax adapts per shell family.
- **Root-cause fix, not a patch**: `z memoria` (a zoxide alias) failed under terminal mode. Diagnosed as running commands **as root** loading root's fish config instead of the user's own — breaking zoxide/mise aliases and functions ("not trusted" noise). Rather than special-casing that one alias, the fix changed terminal mode's execution identity entirely: commands now run **as the service user**, never root, so the user's real shell config always loads; a leading `sudo` in a command is auto-rewritten to `sudo -A` backed by a `SUDO_ASKPASS` helper script that echoes the validated password from an env var — kept only in the shell process's environment (memory), never on disk. This was a meaningful behavior change: terminal mode went from "a root shell" to "you, with effortless sudo."

Verified live at nearly every step against the real dev bot (password prompt, `whoami`, `cd`/persistence, `/exit`, `$` one-shots, wrong-password retries, `z /tmp` resolving, the `sudo -A`/askpass wiring). `go build`/`go test ./...` stayed green throughout, with new tests added per iteration (`TestTermSessionRun`, `TestValidateSudo`, `TestRunOneShot`, `TestFishPerCommand`, `TestApplyPasswordRetry`, `TestAutoSudo`).
