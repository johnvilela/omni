# Agent mode, session commands, provider picks, persona injection, /usage, cron tools, and CI/release (2026-09-01 22:34 – 2026-09-02 00:49)

Opened as a planning-only chat ("what do you suggest as next step? dont execute anything yet"). Landed on: chat mode stays as-is (bare CLI, fast); the missing piece is remote PC control, and the lazy read was **don't build tools/skills/MCP into omni** — that's rebuilding openclaw, the exact weight the project exists to avoid. The agent loop, file tools, bash execution, and MCP already live inside `claude`/`codex`/`gemini`; omni currently strips all of that by running them bare, so "remote control" is un-stripping it on demand behind an `/agent` toggle. Two decisions flagged before building: blast radius (agent mode = a telegram-gated shell on the PC, accepted as deliberate for a single-user bot) and a tiny persona/instructions file (became the later AGENTS.md work). Browser control (the real motivator — LinkedIn upkeep + freelance income) was resolved the same lazy way: omni grows zero browser code, the vendor CLI just reaches `playwright-cli` attached via CDP to the user's **real, already-logged-in Chrome profile** (safest against LinkedIn's anti-automation detection — no fresh-login events, real fingerprint). Behavioral safety over technical: **draft → approve → act**, nothing posts/connects on LinkedIn until an explicit "go" reply; read-only browsing runs free. Job boards with RSS/APIs were named as the cheaper first resort for freelance search, browser reserved for LinkedIn itself.

## Agent mode + session commands (`e43d729`)

The user's concrete ask: `/agent` on telegram, continuing a session; `/new` to start fresh (chat or agent); `/sessions` listing the last 5 with an agent flag and tap-to-resume; playwright-cli + CDP install automated for a **weaker target machine**; memoria hooks enabled in the vendor CLI config so agent-mode sessions keep registering long-term memory. Two Explore agents mapped the telegram/session/store internals and the config/install/CLI-router surface in parallel, then a Plan agent produced the full design, followed almost verbatim:

- **Store**: one-row `active` pointer table (falls back to max-uuid7 for pre-existing DBs — the old rule survives only as fallback), `sessions` gains `agent`/`provider`/`vendor_session_id` via guarded `ALTER TABLE`s.
- **Telegram**: `answer`/new `callback` hooks return a `tgReply{Text, Keyboard}` struct; `callback_query` handling (`answerCallbackQuery` to stop the spinner, then route); reply chunking at telegram's 4096-char cap, rune-safe.
- **Command routing** (`server/command.go`, new): `/new`, `/agent [task]`, `/sessions` (inline keyboard, callback_data = session uuid), default → chat or agent answer depending on `sess.Agent`.
- **Agent answer path** (`server/agent.go`, new): claude `-p <text> --output-format json --dangerously-skip-permissions [--resume <id>]` — verified live that claude **forks a new session id every resumed turn**, so persisting the returned id every turn is load-bearing, not optional. codex `exec [resume <id>] --skip-git-repo-check --dangerously-bypass-approvals-and-sandbox --json -o <tmpfile>`. 15-min timeout, cwd = the agent workspace, no composed history (the vendor session carries context).
- **Workspace seed**: one `CLAUDE.md`/`AGENTS.md` embedded const, written once and never overwritten (persona, phone-friendly output, autonomy/timeout note, the playwright-cli+CDP browser playbook against a persistent `chrome-profile/`, the LinkedIn draft→approve rule).
- **Installer**: idempotent `agent dependencies` block in `install.sh` (dev.sh untouched — dev box already has it), every step `command -v`-guarded: chromium+node+npm via pacman/apt, `npm install -g playwright`, the agent workspace + `chrome-profile/`, memoria binary from GitHub latest release, `memoria setup --client claude-code,codex --global` + a workspace `memoria bootstrap`.

Live-verifying the seeded browser instructions on the **dev machine** surfaced a real trap: `playwright-cli` there is an omarchy npx wrapper that resolves the `playwright` test-runner bin first, so driving commands need an extra `cli` prefix (`playwright-cli cli attach --cdp=…`) — the bare `playwright-cli attach` in the seed is correct only for the target machine's real npm-installed bin. Recorded as [[gotchas/playwright-cli-wrapper-vs-npm-bin]]. TDD throughout, full suite/vet/gofmt clean, verified live on the dev bot end to end (`/agent list the files in your workspace` did real tool use; a follow-up continued the same agent session). Committed `e43d729` — "feat(telegram): add agent mode and session commands" (24 files, +1204/−74). Full contract now lives in [[api]] and [[chatbot-memory]].

Immediate follow-up: registered `/new`, `/agent`, `/sessions` via `setMyCommands` on every telegram connect (best-effort, never blocks connect) so they show as a native "/" autocomplete menu — locked by `TestTelegramRegisterCommands`.

## Persona injection via AGENTS.md (`c242f94`)

Ask: an `~/.config/omni/AGENTS.md` for personality/utility, injected before any session-starting message and after every compaction "so the ai agent never forgets it," explaining memoria MCP usage, instructing concise/straightforward answers with clarifying questions when a request is ambiguous. Delivered stronger than asked: since chat is **stateless** (the whole prompt is re-sent every turn), the persona is injected at the **top of every composed chat prompt**, not just at session-start/post-compaction — literally unforgettable. Seeded write-once at server boot, owner edits apply on the next message with no restart, always included whole and budget-counted like memory. Default content: identity (omni, single owner), concise phone-friendly answers, ask a short clarifying question instead of guessing on ambiguity, mirror the user's language, plain text (no markdown — telegram shows it raw), trust the long-term-memory section instead of re-asking. The **agent workspace** seed (separate file, separate purpose) gained a matching memoria-MCP section: search before non-trivial tasks, `memoria_write_page` for durable findings, `memoria_recall` for past sessions, hooks capture automatically — plus the same language-mirror and ask-before-ambiguous rules. Dev workspace's old seed files were deleted so the next `/agent` picks up the new content. Committed `c242f94` — "feat(chat): inject editable persona from config AGENTS.md every turn" (8 files, +205/−17). Full design in [[chatbot-memory]] and [[api]].

## Plan review → cron tools (`33accb9`)

A "what's next, don't build yet" check-in assessed the platform as complete (chat+memory+persona, agent mode, session management, /usage, installer) but the *mission* (LinkedIn/freelance) untouched and nothing deployed off the dev box. Suggested order: push+deploy, run a first real LinkedIn task, then proactive tasks, then unblock the poller. The user asked to annotate the poller item into [[tasks]] and, as the actual next build, create **cron tools**: create scheduled jobs from natural language ("remind me... every day at 8am", "send me a message every wednesday"), list/edit/delete existing ones, and let the model suggest job creation. Delivered:

- SQLite `crons` table (5-field cron schedule), a ~60-line hand-rolled parser (`*`, lists, ranges, steps, dow 0|7=sunday, vixie dom/dow OR rule) — no cron library, matching the project's existing "stdlib/hand-rolled first" stance.
- A minute ticker firing matches; missed minutes are skipped (classic cron semantics, deliberate).
- Three kinds: `message` (proactive send as-is), `prompt` (single-turn persona-aware answer, doesn't touch the active session), `agent` (one-shot fresh-context agent run in the workspace).
- Proactive delivery to every approved telegram pairing — omni's first bot-speaks-unprompted path.
- **The tool protocol**: `cronPrompt` injects the live job list + a `TOOL:cron_add/cron_edit/cron_delete {json}` contract into every chat prompt (budget-counted like persona/memory), so listing/suggesting needs no extra round-trip; `applyTools` executes TOOL lines in the reply and replaces them with deterministic confirmations **before** the assistant turn is stored — history carries confirmations, never raw TOOL lines. Single-pass by design.
- `/crons` lists jobs with a 🗑 inline-keyboard delete button per job (`callback_data "cron-del:<id>"`, routed apart from session-resume uuids by prefix).

Verified fully live, not just by test: inserted a test cron for two minutes out, confirmed the proactive fire arrived unprompted on the phone; confirmed the `/crons` 🗑 delete button worked; confirmed a plain-chat ask ("remind me to drink water every day at 8am") produced a `⏰ #2 created …` confirmation, proving the NL→tool round trip. Committed `33accb9` — "feat(server): add cron scheduler with llm tool protocol and /crons" (21 files, +781/−10). Full contract in [[api]]; deferred-work tracking in [[tasks]].

## CI / release setup (`9751c7e`)

Ask: set up GitHub Actions like [[memoria]]'s, using memoria's own cross-project wiki as the reference for its pipeline. Read memoria's actual `.github/workflows/*.yml` and `scripts/build.sh` directly and mirrored the shape: `ci.yml` (PRs to master — `go vet` + `go test -race` + a version-bump gate: Go/go.mod changes must bump `version/version.go`'s `Version` const to a value whose tag doesn't exist yet) and `release.yml` (push to master — tests, then if the tag for the current Version is new: `scripts/build.sh all` → sha256 checksums → `gh release create` with generated notes; pushing a version bump to master **is** the release action). `build.sh` gained an `all` release-matrix mode: both binaries × linux amd64/arm64 into `dist/` (verified locally, `dist/` gitignored) — linux-only since omni targets linux PCs, unlike memoria's darwin targets. Deliberate deviations from memoria, noted in the wiki: omni's `Version` carries a `v` prefix so tags use it verbatim (memoria's is bare and prepends `v`); gotestsum skipped (zero tool deps); **no branch-protection ruleset** — omni still commits straight to master, unlike memoria's PR-required/no-bypass ruleset, revisit only if the workflow ever moves to branch+PR (a ruleset now would have blocked the pending push). Committed `9751c7e` — "ci: add pr version gate and auto-release on master push" (5 files, +105/−1). Full detail in [[install]].
