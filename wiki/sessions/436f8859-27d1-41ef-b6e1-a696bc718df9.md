# `/context` progress bar, then model-aware chat token budgets (2026-09-02, 13:30–14:01)

Opened with a concrete feature ask: a Telegram `/context` command showing a progress bar of context usage broken down by AGENTS.md files, skills, MCP, and messages, with an open invitation ("Ask me anything about this new feature") that the work went ahead and answered by building a sensible default rather than a back-and-forth. Explored the existing server layout (telegram command wiring, session store, persona/memory/cron-prompt injection paths, the `command_test.go`/`persona.go` shape) before implementing.

Delivered `/context` (new `server/context.go`) that adapts to the active session type:

- **Chat sessions** — a bar against the compose budget, mirroring `composePrompt`'s own budget walk: persona (AGENTS.md), memory, messages (how many of the recent turns fit), free space.
- **Agent sessions** — a bar against the model's real context window (claude 200k, codex 272k at the time). The total is real, not estimated: each agent turn now stores the CLI-reported context size in a new `sessions.last_ctx` column (claude: input+cache tokens; codex: last `turn.completed` input). File categories (workspace/user AGENTS.md, skills — frontmatter only, body never enters context) are bytes/4 estimates from disk; MCP + system tools can't be read from disk at all, so that line is shown as the honest *remainder* of the real total minus the estimates, rendered as `?` before the session's first turn.

Touched: `context.go` (new), `store.go` (the `last_ctx` column + `SetSessionCtx`), `agent.go`/`answer.go` (context capture), `command.go` + `telegram.go` (wiring), `context_test.go`. Full contract landed in [[api]] and [[decisions/context-command-remainder]]. Explicitly skipped for later: per-skill/per-MCP-server drill-down and codex multi-turn context precision — tracked in [[tasks]].

## Why is chat capped at 8k when claude/codex have 1M?

Immediate follow-up question after seeing the bars. Answer: it was deliberate cost control, not a capability ceiling — chat sessions re-send the *entire* composed prompt (persona + memory + history) as one plain, uncached prompt on every single message, so the budget is a per-message cost/quota cap, and the 1M windows belong to the big agent-session models while bare chat defaults to cheap small models. First fix: bumped `defaultTokenBudget` in `server/chat.go` from 8000 to 100,000, with the cost tradeoff noted in the comment. Side effect flagged at the time: history now only overflows into memoria long-term memory much less often than at 8k.

## Model-aware budget with a clamp + warning

A further ask refined this: give large-context models (fable, opus-5) their full room, but if the user's selected model has a *smaller* window than the configured budget, warn on `omni status` and clamp automatically instead of letting requests 400. This superseded the flat 100k default from minutes earlier. Delivered `chatBudget(provider)` in `server/chat.go`:

- `token_budget` default raised again, to 500k, but the effective budget is always clamped to 80% of the chat model's context window (headroom for the reply and estimate error), via a `modelWindows` prefix table.
- The **default** clamps silently — haiku ends up around 160k, fable gets the full 500k, no warning either way.
- An **explicit** `token_budget` that exceeds the picked model's window sets a `clamped=true` flag, surfaced as a `BudgetNote` on `llmStatus` (rendered in `omni status` via `renderLLM`) and as a ⚠ line in Telegram `/context`.
- The sticky `@provider` pin and cron `prompt` jobs resolve their budget through the same `chatBudget` path, so a session pinned to a small-model provider gets that model's clamp.
- Caveat carried into the code and wiki: on the oauth CLI path the actual model in use isn't knowable from omni, so the clamp stays conservative (~200k-class) until the user picks a model explicitly via `omni llm model` — that's what unlocks the 500k tier.

New `TestChatBudget` covers silent clamp, warned clamp, big-model passthrough, and small explicit budgets; full server+cli suite green throughout. This final design is the one recorded as current fact in [[decisions/chat-budget-model-clamp]]; the 8k→100k step above was an intermediate stop, not the shipped behavior.
