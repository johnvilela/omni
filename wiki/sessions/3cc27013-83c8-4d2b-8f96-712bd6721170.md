# Gum-powered scripts, guardian one-tap update, terminal upgrades, and the /ops panel (2026-09-03, 16:16–21:58)

Four features shipped back to back, each verified live and committed separately.

## Gum UX for install/dev/uninstall scripts (v0.18.1)

Opened with: "Update the scripts install.sh, uninstall.sh and dev.sh to use the package gum for bash to make the UX better." Converted long-running steps (go test, scripts/build.sh) to run under `gum spin --show-error` (quiet on success, full output on failure, exit code still propagates for `set -e`), warnings to `gum log --level warn`, step headers to `gum style`, and the uninstall.sh delete prompt from `read -rp` to `gum confirm --default=false` (same default-no semantics, `--yes` still bypasses). A follow-up ask ("Also display the ASIIC art on those scripts") added a hardcoded cyan "OMNI" ASCII banner via `gum style` to all three, each tagged with a faint line ("installer"/"dev install"/"uninstaller"). Each script gained a one-line guard that hard-fails with an install hint if `gum` is missing — no echo-fallback shims. Hit and worked around the `gum spin` env-prefix gotcha (it execs directly, no shell — needs `env VAR=1 cmd`, not `VAR=1 cmd`), verified by a smoke test before relying on it; recorded as [[gotchas/gum-spin-execs-without-shell]]. Version bumped to v0.18.1 (logic unchanged). Committed `3cdc885`, pushed.

## Guardian one-tap update + rollback (v0.19.0, released as part of v0.20.0)

A screenshot described the feature: instead of guardian's "rerun scripts/install.sh" text alert when a newer omni release exists, offer inline Telegram buttons — Update / Changelog / Ignore — with automatic download, checksum verify, binary swap, restart, health check, and auto-rollback if the new server doesn't come up healthy. Two Explore agents mapped the guardian internals (it can send Telegram messages but never polls `getUpdates`, so it cannot receive taps) and the server's callback/approval-gate plumbing, then a Plan agent designed the split: **guardian detects+offers+executes; server receives taps and records intent as data-dir files** (`update.request`, `update.ignore`), kicking the guardian immediately via `systemctl --user start --no-block`. AskUserQuestion settled: omni-only scope, changelog posted in-chat (not a URL button), Ignore = skip this version, and the update starts immediately on tap. Implemented per plan — checksum-verified atomic binary swap with `.prev` backups kept as a manual escape hatch, `waitServer(tag)` health check requiring the exact new version, rollback accepting any healthy version. Full design landed in [[decisions/one-tap-update]] (written to the wiki mid-session, cross-linked from [[decisions/guardian-update-watch]]). This work was committed on its own (`a6a1a6b`) but the version bump rode the *next* feature's commit, so both released together as v0.20.0, not v0.19.0.

## Terminal mode: `/interrupt`, idle TTL, output streaming (v0.20.0)

Another screenshot, same session: add `/interrupt` (^C without killing the terminal session), an idle timeout so `/terminal` auto-closes, and live output streaming so long commands aren't silent. Two Explore agents mapped `server/terminal.go`'s two execution models (persistent bash/zsh process vs per-command `fish -c`) and found zero existing process-group/signal handling. A live experiment (piped bash + `trap ':' INT` + group SIGINT) confirmed the load-bearing trick before coding: a `trap` *handler* survives in the shell but resets to default in children, so a group SIGINT kills the running command while the shell itself lives — `trap '' INT` (SIG_IGN) would NOT work, since it's inherited across exec. A Plan agent then designed and flagged several real races in the initial sketch (send-on-closed-channel from a TTL timer, a `ts.cwd` data race, unnecessary CancelFuncs for the persistent shell) which were fixed before implementation. Shipped: `/interrupt` for bash/zsh via `syscall.Kill(-pgid, SIGINT)`, for fish/`$` one-shots via a stored `context.CancelFunc` wired to `exec.CommandContext`'s `c.Cancel` (group SIGINT) + `c.WaitDelay`; a 5-minute idle TTL (`time.AfterFunc`, reset per command, never fires while busy) with a pinned-dashboard `🖥 TERMINAL · <cwd>` indicator; and output streaming (progress message after 5s, edited every 3s with a rune-safe tail, finished in place or chunked). Forced a real fix along the way: teardown and the poller's channel send now share `termMu` — the TTL timer had turned the old unlocked `close(cmds)` into a send-on-closed-channel panic vector. Full design in [[decisions/terminal-mode]] (already updated in the wiki with the full v0.20.0 section). Committed `758fac5` (carries the v0.20.0 version bump); pushed together with the guardian-update commit, so v0.20.0 is the first release to carry both features — the release *after* it is what will exercise the new update-button flow end to end.

## `/ops` quick-actions panel (v0.21.0)

Final screenshot: a Telegram panel bundling Status/Doctor/Logs/Disk/Restart/Update/Terminal into one inline keyboard. An Explore agent confirmed each button could reuse existing plumbing with near-zero new code — Doctor as a literal `$ omni doctor` one-shot (gets streaming + `/interrupt` for free, lipgloss auto-detects the non-TTY pipe and emits plain text), Logs as `journalctl` with the existing bot-token redaction pattern, Update as the existing un-throttle-and-kick-guardian trick already used by `ignoreUpdate`. The one real gotcha surfaced by exploration: a synchronous restart fired inside a Telegram callback would be replayed forever, because Telegram only acks an update on the *next* `getUpdates` call (not on `answerCallbackQuery`), and a backgrounded `sleep && restart` child dies with the server's own cgroup. Fixed with `systemd-run --user --on-active=2s --collect` — a transient unit outside the server's cgroup, with 2 seconds of slack for the poller to issue its next `getUpdates` before the process dies. Restart also sits behind a confirm tap. Full design in [[decisions/ops-menu]] (written to the wiki mid-session). Committed `cdf3fe0` (version bump to v0.21.0), then `docs(wiki)` `571e572`.
